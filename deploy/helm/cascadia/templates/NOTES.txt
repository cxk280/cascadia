Cascadia LLM gateway is being installed.

1. Wait for the proxy to come up:

   kubectl --namespace {{ .Release.Namespace }} rollout status deployment/{{ include "cascadia.fullname" . }}

2. Port-forward to test locally:

   kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "cascadia.fullname" . }} 8080:{{ .Values.service.port }}

3. Hit the health endpoint:

   curl http://localhost:8080/health

4. Send a chat completion (note: Phase 7 requires `provider/model` prefix in the policy file, but the request body's `model` field is overridden by cascade routing — any non-empty string works):

   curl http://localhost:8080/v1/chat/completions \
       -H 'Content-Type: application/json' \
       -d '{"model":"auto","messages":[{"role":"user","content":"hi"}]}'

{{- if not .Values.config.persistBodies }}

ℹ  `config.persistBodies` is `false`. Shadow pairs will still be written and the
   cascade decision metadata is preserved, but the judge worker will see
   request/response bodies only via the shadow_pairs columns — the events
   table will not carry verbatim bodies. If you don't carry PII (or you've
   redacted at the application layer), set `config.persistBodies: true` for
   the strongest closed-loop quality signal. See the chart README's
   "Data residency" section for the full trade-off.
{{- end }}

   NOT stable between minor versions. Lock the chart by `git checkout <tag>`
   *before* every `helm upgrade` — `helm install --version` only constrains
   registry-based installs, not the local-path install used here. Read
   CHANGELOG.md before upgrading. Pulling from `main` unlocked is the
